# Патч: блокировка окна «Активация разрешения» и активность кнопки «Подать заявку» — ревизия 2

Проект: **WebShelf** · Базовый коммит: **a6e222a** («Добавлена форма запроса на регистрацию», ветка main) ·
Дата: 08.11.2026 · Задача (ревизия 1): 1) при неправильном вводе пермита окно «Активация разрешения» не должно возвращать на форму входа — поведение как при неверной паре логин/пароль, но таймер включается после первой попытки, а не пятой; таймер оформлен как на форме входа; форма входа очищена от более не используемых элементов. 2) кнопка «Подать заявку» неактивна по умолчанию и активизируется только при полностью корректной форме, деактивируясь при любом исправлении, делающем данные некорректными.
Правки ревизии 2: 3) заблокированные кнопки не должны визуально реагировать на нажатие; 4) на форме «Активация разрешения» красное сообщение «Неверный ключ разрешения.» не требуется (таймер включается уже после первого неправильного ввода); добавить постепенное увеличение времени блокировки — каждый раз в два раза, до предела в 15 минут; оранжевый блок с таймером должен быть под кнопкой (стиль как на форме входа); обновление страницы не должно сбрасывать таймер.

## 2. Поведение по пунктам задачи

1) **Окно «Активация разрешения» при неправильном вводе** — пользователь не возвращается на форму входа. Поведение как при неверной паре логин/пароль: окно остаётся открытым, включается блокировка — с той разницей, что таймер включается после **первой** неудачной попытки, а не после пятой. **Красное сообщение «Неверный ключ разрешения.» не выводится**: таймер включается всегда, и оранжевый блок с обратным отсчётом сам объясняет причину. **Постепенное увеличение времени**: первая блокировка — 15 с, каждая следующая вдвое дольше (15 → 30 → 60 → 120 → 240 → 480 → 900 с), предел — **15 минут**; после 15 минут без неудач или успешной активации эскалация начинается заново. **Оформление — как на форме входа**: оранжевый блок `ws-message-lockout` «Повторите попытку активации через N с.» расположен **под кнопкой**, заблокированные поле и кнопка, текст кнопки «Активация временно заблокирована». **Обновление страницы не сбрасывает таймер**: состояние (момент окончания и номер блокировки) хранится на сервере в `PermitActivationGuard` (singleton, учёт по IP — как LoginGuard для формы входа); после F5 отсчёт продолжается с того же остатка при открытии окна. Пустой ввод не блокирует (аналог `required` формы входа). Ошибка сервера — сообщение без блокировки, повторная попытка сразу.
2) **Форма входа очищена** от более не используемых элементов: кнопка «Зарегистрироваться» — обычная кнопка открытия окна активации, без блокировки с обратным отсчётом; удалены все связанные поля и методы.
3) **Кнопка «Подать заявку»**: по умолчанию `disabled`; активируется, только когда вся форма заполнена корректно (`RegistrationFormValidator.IsApplicationValid`: валидные ФИО/e-mail/телефон + дано согласие); деактивируется при любом изменении, делающем форму некорректной — снятие галочки чек-бокса, удаление данных, неверный формат (проверка перевычисляется на каждом вводе благодаря `@bind:event="oninput"`). Показ ошибок полей не зависит от состояния кнопки.
4) **Заблокированные кнопки не реагируют на нажатие визуально**: для `ws-btn-primary` («Войти» при блокировке входа, «Продолжить» при блокировке/проверке пермита, «Подать заявку» до готовности формы), `ws-btn-secondary` и кнопки показа пароля hover/active-эффекты (подсветка, тень, сжатие `scale(0.98)`) применяются только в состоянии `:not(:disabled)`; в `:disabled` зафиксировано `transform: none`; заблокированный чек-бокс «Запомнить меня» показывает курсор not-allowed вместо указателя.

## 3. Как применить

Вариант 1 — поверх рабочей копии репозитория (коммит a6e222a):

1. Распаковать архив.
2. Скопировать файлы из каталогов `WebShelf/`, `WebShelf.Tests/` и `WebShelfDocs/` архива в одноимённые каталоги репозитория (с заменой), README.md — в корень.
3. Пересобрать решение: `dotnet build WebShelf.slnx -c Debug`.
4. Прогнать тесты: `dotnet test WebShelf.Tests/WebShelf.Tests.csproj -c Debug`.

Вариант 2 — через git:

```bash
git apply permit-lockout-and-submit-button-a6e222a.patch
```

Коммитов в репозиторий патч не отправляет (п. 1 правил AGENTS.md).
