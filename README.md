Проект: **WebShelf** · Базовый коммит: **8b09112** («Добавлен журнал версий политик обработки cookie и персональных данных», ветка main) ·
Дата: 11.11.2026 · Задача: доработать таблицу «Заявки на регистрацию» под хранение всех данных формы (включая версии политик согласий, время подачи UTC, идентификатор УЗ AD) и реализовать подачу заявки кнопкой «Подать заявку» со списанием пермита после вставки.

## 2. Поведение по пунктам задачи

1) **Таблица хранит все данные формы** — ФИО (patronymic NOT NULL), телефон, e-mail, версии политик ПД и cookie, время подачи по UTC с точностью до секунды, идентификатор УЗ AD (NULL — заявка не принята, заполнен — принята; единственный nullable-столбец), служебный `id`. Все столбцы, кроме `ad_object_guid`, NOT NULL. `birth_date` убран.
2) **Кнопка «Подать заявку» записывает заявку** (идентификатор УЗ AD остаётся NULL) со списанием пермита после вставки в той же транзакции; при успехе — сообщение о входе после одобрения администратором.
3) **Связь с AD без потери** — `ad_object_guid` (`uuid`): objectGUID неизменяем и не переиспользуется; `UNIQUE(ad_object_guid)` — однозначная связь в обе стороны.
4) **Уникальные e-mail и телефон** — предупреждение и блокировка кнопки при нахождении в таблице (проверка по касанию поля), ограничения `UNIQUE` в БД + повторная проверка при подаче как страховка от гонки; e-mail хранится и сравнивается в нижнем регистре.
5) **Согласие на политику cookie** — обязательный чек-бокс по правилам согласия на ПД; номер редакции фиксируется в заявке.
6) **Риски обновления структуры игнорируются** — боевых копий нет; обновление структуры к каркасу v5 выполняется штатным механизмом DbBootstrapper (дамп перед изменениями — автоматически).

## 3. Как применить

Ветка `z` содержит коммит патча; детали — в инструкции к коммиту. Сборка: `dotnet build WebShelf.slnx -c Debug`, тесты: `dotnet test WebShelf.Tests/WebShelf.Tests.csproj -c Debug` (интеграционные — при заданной `WEBSHELF_TEST_PG`).

## 4. Тесты

- `WebShelf.Tests/RegistrationRequestServiceTests.cs` — **новый**, интеграционные `[PostgresFact]`: проверка контактов (пустая таблица, занятые, регистронезависимость e-mail), успешная подача (содержимое строки: ФИО, телефон, e-mail в нижнем регистре, редакции политик, `submitted_at` без долей секунды, `ad_object_guid` NULL, счётчик −1), пермит не найден/исчерпан, дубликаты e-mail/телефона (счётчик не тратится), структура таблицы (нет `birth_date`, `patronymic` NOT NULL, несколько NULL в `ad_object_guid` не конфликтуют, повторная привязка одного objectGUID запрещена), сходимость каркаса (повторное сравнение живой схемы с каркасом — без расхождений).
- `WebShelf.Tests/RegistrationFormValidatorTests.cs` — cookie-согласие (ошибка/null), `IsApplicationValid` с двумя согласиями (успех, снятие любого, пустая форма, очистка/порча полей).
- `WebShelf.Tests/RegistrationApplicationFormTests.cs` — чек-бокс cookie-согласия со ссылкой на политику, 7 обязательных элементов ввода, кнопка заблокирована/`type="button"`, отсутствие ошибок и сообщения об успехе до подачи (сервис подменяется фейком).

Результат прогона (Linux, .NET SDK 10.0.404, PostgreSQL 17.5, `WEBSHELF_TEST_PG` задан): **696 тестов, 0 упало, 691 прошло, 5 пропущено** (пропущенные — Windows-специфичные тесты KeyStore: HKCU/DPAPI). Базовый прогон на коммите 8b09112 до изменений в том же окружении: 680 тестов, 0 упало — падений, не связанных с задачей, нет.
