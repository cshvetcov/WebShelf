# WebShelf

Браузерное приложение для хранения и обработки проектной документации,
учёта изменений и администрирования рабочих процессов в проектных организациях
промышленного и гражданского строительства. Работает под Windows x64 в среде
Active Directory с базой данных PostgreSQL.

## Возможности

- **Аутентификация через Active Directory** — проверка учётных данных
  (LDAP `Negotiate + Signing + Sealing`) и членства в группах WebShelf.
- **Защита от перебора паролей** — учёт неудачных попыток по IP-адресу и по
  пользователю с эскалацией длительности блокировки.
- **Шифрование секретов** — пароли сервисных учётных записей и TLS-сертификата
  автоматически шифруются мастер-ключом (AES-256-CBC + HMAC-SHA256,
  Encrypt-then-MAC) и хранятся в конфигурации в зашифрованном виде.
- **Мастер-ключ** — генерируется и хранится в реестре под защитой DPAPI
  текущей учётной записи Windows; в памяти — с sliding-TTL кэшированием.
- **Защитные HTTP-заголовки** — Content-Security-Policy, X-Frame-Options,
  X-Content-Type-Options, Referrer-Policy, Permissions-Policy.
- **Устойчивые сессии** — ключи Data Protection хранятся на диске под защитой
  DPAPI, перезапуск приложения не разлогинивает пользователей.
- **Единственный экземпляр** — глобальный мьютекс на учётную запись Windows.
- **Структурированное логирование** — Serilog, ежедневные файлы логов.

## Требования

- Windows x64 и .NET 10 SDK (для сборки) или .NET 10 Runtime (для запуска).
- Доступный контроллер домена Active Directory.
- Сервер PostgreSQL 14+ (для сборки достаточно более ранних версий).
- Сервисные учётные записи: в AD и в PostgreSQL.
- При схеме `https` — PFX-сертификат сервера (см. раздел «TLS-сертификат»).

## Сборка и запуск

```sh
# Сборка
dotnet build WebShelf.slnx

# Запуск в режиме разработки
dotnet run --project WebShelf/WebShelf.csproj

# Публикация (Release)
dotnet publish WebShelf/WebShelf.csproj -c Release -o publish
```

Приложение читает `Server.conf` из каталога с бинарниками. При первом запуске
скопируйте шаблон и заполните ключевые поля:

```sh
copy WebShelf/Server.conf.template WebShelf/Server.conf
```

При старте приложение проверяет конфигурацию, домен и базу данных; при любой
ошибке запуск прерывается с записью в лог (`logs/webshelf-ГГГГММДД.log`).

## Конфигурация Server.conf

| Ключ | Назначение |
| --- | --- |
| `scheme` | `http` или `https` (без учёта регистра) |
| `port` | Порт прослушивания, 1–65535 |
| `certpath` | Путь к PFX-сертификату (только при `https`) |
| `certpass` | Пароль PFX в открытом виде — шифруется и очищается автоматически |
| `scertpass` | Пароль PFX, зашифрованный мастер-ключом (заполняется автоматически) |
| `domainname` | Имя домена Active Directory (FQDN, например `company.local`) |
| `domainuser` / `domainpass` | Сервисная учётная запись домена — шифруются и очищаются автоматически |
| `sdomainuser` / `sdomainpass` | Учётные данные домена, зашифрованные мастер-ключом |
| `dbhost` | Хост PostgreSQL (имя или IP) |
| `dbport` | Порт PostgreSQL, по умолчанию 5432 |
| `dbname` | Имя базы данных |
| `dbsslmode` | `Disable`, `Allow`, `Prefer`, `Require` (по умолчанию), `VerifyCA`, `VerifyFull` |
| `dbuser` / `dbpass` | Сервисная учётная запись БД — шифруются и очищаются автоматически |
| `sdbuser` / `sdbpass` | Учётные данные БД, зашифрованные мастер-ключом |
| `rolettl` | TTL кэша роли пользователя, секунд (10–300; по умолчанию и вне границ — 60) |

Открытые пароли (`domainuser`, `domainpass`, `dbuser`, `dbpass`, `certpass`)
при первом успешном запуске шифруются мастер-ключом, переносятся в
соответствующие ключи `s…`, а открытые значения очищаются. Файл конфигурации
заменяется атомарно (`File.Replace`). Передавать пароли в открытом виде нужно
только один раз — при первичной настройке.

## TLS-сертификат

При `scheme=https` обязателен PFX-сертификат с закрытым ключом:

1. Получите сертификат (внутренний ЦС, Let's Encrypt или самоподписанный
   для тестов) и экспортируйте его в PFX вместе с закрытым ключом.
2. Укажите путь и пароль в `Server.conf`:

```ini
scheme=https
port=443
certpath=C:\certs\webshelf.pfx
certpass=ПарольPfxФайла
```

3. При первом запуске пароль будет зашифрован и перенесён в `scertpass`,
   а `certpass` очищен. Относительный `certpath` ищется рядом с приложением.
   Для PFX без пароля оставьте `certpass` пустым.

При загрузке сертификата приложение проверяет наличие закрытого ключа и
предупреждает в логе, если срок действия истёк или истекает менее чем через
14 дней. Сертификат (*.pfx) и закрытые ключи (*.key, *.pem) исключены из
репозитория через `.gitignore`.

## Active Directory

Пользователи WebShelf должны состоять в группе AD:

```
WebShelf-{12 символов InstanceId в нижнем регистре}-Users
```

InstanceId (ULID) генерируется автоматически при первом запуске (Release) и
хранится в `HKEY_CURRENT_USER\Software\WebShelf\Encryption` под защитой DPAPI.
Текущий короткий префикс выводится в лог при старте. Ролевые группы
(`WebShelf-{id}-Administrator`, `WebShelf-{id}-Director`,
`WebShelf-{id}-BIMManager` и т.д.) создаются приложением автоматически при
старте при наличии у сервисной учётной записи прав на создание групп;
роль пользователя вычисляется по членству в них (без групп — Гость, при
нескольких группах — старшая роль). Смена ролей применяется в открытых
сессиях без перезагрузки страницы (фоновый опрос групп каждые 30 секунд,
TTL-кэш, свежая проверка перед критичными операциями). В Debug-сборке
InstanceId фиксирован (`WebShelf-000000000000-*`) — удобно для отладки
на разных машинах.

## Безопасность

- Мастер-ключ — в реестре HKCU под защитой DPAPI; расшифровать блоб может
  только код под той же учётной записью Windows.
- Проверка целостности шифрованных данных — HMAC-SHA256, сравнение за
  постоянное время (`CryptographicOperations.FixedTimeEquals`).
- Ключевой материал в памяти обнуляется после использования.
- Форма входа защищена antiforgery-токеном; выход выполняется только
  POST-запросом с токеном (защита от logout-CSRF).
- Реальные имена учётных записей в логи не попадают (`SystemAccount` /
  `UserAccount`).
- Cookie аутентификации: `HttpOnly`, `SameSite=Lax`, при `https` — всегда
  `Secure`; срок жизни — 8 часов или 14 дней с опцией «Запомнить меня».

## Тесты

```sh
dotnet test WebShelf.Tests/WebShelf.Tests.csproj
```

Покрываются: криптографический движок (`CryptoEngine`: циклы всех 8 перегрузок,
целостность, порядок проверок «MAC до AES», эталонная константа замороженного
формата, валидация) и переходные фасады делегатов (`EncryptionService`),
хранилище ключей (`KeyStore`: создание ключей,
InstanceId и мастер-ключ в HKCU под защитой DPAPI — идемпотентность,
round-trip записи/чтения, отказы повреждённых данных, очистка кэша), защита
от перебора (`LoginGuard`), эндпоинты входа/выхода (`AccountEndpoints`: таблица
`IsLocalUrl`, ветки CSRF, блокировка перебора, отказ домена, различение
fetch-запроса и обычного перехода при выходе), нормализация имён
пользователей (`AdNames`), формирование списка групп безопасности из шаблонов
имён (`Domain`),
жизненный цикл `InstanceId` (`Data`), парсер `Server.conf`
(`ServerConfigParser`: key=value — комментарии, дубликаты, регистр,
UTF-8/BOM, CRLF, файл без валидных записей), запись `Server.conf`
(`SecureCredentialsWriter`: защищённые учётные данные с затиранием открытых,
сохранение комментариев и порядка строк, атомарная замена файла,
байтовый формат) и инициализаторы секций конфигурации (`DomainSection`,
`DatabaseSection`, `CertificateSection`: отказы до обращения к мастер-ключу,
схема http без сертификата; миграция учётных данных при чтении —
на уровне `Data.ReadConfigAsync`),
валидация параметров БД (`Database`),
заголовки безопасности (middleware), ролевая модель (каталог ролей:
состав, старшинство, шаблоны и имена групп, вычисление роли по группам,
Гость, пересечение ролей; TTL кэша роли и его границы; уведомления об
изменении роли; расширения `ClaimsPrincipal`; регистрации сервисов ролевой
модели в DI — сборка контейнера без неразрешимых зависимостей). Тесты, зависящие от реестра и DPAPI
(хранилище ключей `KeyStore`, полный конструктор `Domain`/`Database`, формирование списка
групп, миграция учётных данных при чтении `Server.conf`), выполняются только на Windows — на других ОС они автоматически
пропускаются; реестровые тесты и их потребители выполняются в одной
непараллельной коллекции.

## Версионирование

Версия вычисляется автоматически по истории Git
(Nerdbank.GitVersioning, `version.json`): текущая схема
`0.1-alpha.{height}`. Сведения о версии и коммите пишутся в лог при старте.

## Структура репозитория

```
WebShelf/              Приложение Blazor Server
  Classes/Crypto/      Криптография: хранилище ключей (InstanceId и мастер-ключ:
                       HKCU + DPAPI) и движок шифрования (AES-256-CBC + HMAC-SHA256)
  Classes/Service/     Системные сервисы (конфигурация, шифрование данных, защита входа)
  Classes/Service/Configuration/   Конфигурация Server.conf: парсер (key=value)
                       и запись защищённых учётных данных (с сохранением
                       комментариев и порядка строк, атомарная замена файла)
  Classes/Service/Configuration/Sections/   Инициализаторы секций конфигурации:
                       домен AD, подключение PostgreSQL, TLS-сертификат
  Classes/DB/          Работа с PostgreSQL
  Classes/DC/          Работа с Active Directory
  Classes/Security/    Ролевая модель, эндпоинты входа/выхода
  Components/          Razor-компоненты (страницы, макет, окна)
  wwwroot/             Статические файлы (css, js)
WebShelf.Tests/        Юнит-тесты (xUnit v3)
WebShelfDocs/          Документация проекта (хранилище Obsidian)
```
