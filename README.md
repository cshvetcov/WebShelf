## 2. Поведение по пунктам задачи

1) **Футер** — ссылка на статическую страницу политики обработки персональных данных; стиль и поведение страницы полностью аналогичны странице политики cookie (статичный документ `wwwroot`, отдаётся веб-сервером как есть, редактируется после развёртывания без пересборки).
2) **Надпись WebShelf из футера удалена** (проверяется тестом `Render_Footer_NoWebShelfAppName`).
3) **Ссылки на политики — в центре футера, с визуальным разделением**: контейнер `ws-footer-links` центрируется (`justify-content: center`), между ссылками декоративный разделитель `|` (`aria-hidden`).
4) **Форма заявки на регистрацию**: Фамилия, Имя, Отчество, E-Mail, телефон +7 (XXX) XXX-XX-XX; все поля обязательны; автоматическая проверка форматов телефона и e-mail по мере ввода (маска телефона, ошибки под полями); чек-бокс согласия на обработку ПД со ссылкой на политику по законодательству РФ (152-ФЗ, ч. 1 ст. 9; приказ РКН № 18); кнопка «Подать заявку» — без поведения (заглушка, обработка появится вместе с логикой регистрации). Закрытие окна — возврат к форме входа, введённые данные сбрасываются.
5) **Кнопка «Продолжить»**: пермит из поля ищется в БД точным совпадением; найден и счётчик > 0 — открывается окно подачи заявки; не найден, пуст или счётчик = 0 — окно ввода пермита закрывается, пользователь возвращается на окно входа, кнопка «Зарегистрироваться» блокируется на 15 с с обратным отсчётом («Регистрация доступна через N с.»). Ошибки сервера оставляют окно открытым с сообщением и не включают блокировку.

## 3. Как применить

Вариант 1 — поверх рабочей копии репозитория (коммит 2cf3a46):

1. Распаковать архив.
2. Скопировать файлы из каталогов `WebShelf/`, `WebShelf.Tests/` и `WebShelfDocs/` архива в одноимённые каталоги репозитория (с заменой).
3. Пересобрать решение: `dotnet build WebShelf.slnx -c Debug`.
4. Прогнать тесты: `dotnet test WebShelf.Tests/WebShelf.Tests.csproj -c Debug`.

Вариант 2 — через git:

```bash
git apply registration-flow-2cf3a46.patch
```

Коммитов в репозиторий патч не отправляет (п. 1 правил AGENTS.md).

- `WebShelf.Tests/RegistrationFormValidatorTests.cs` — форматы ФИО/e-mail/телефона (граничные случаи, длины 100/254), тексты ошибок, согласие, маска телефона на всех промежуточных состояниях, идемпотентность.
- `WebShelf.Tests/RegistrationPermitCheckerTests.cs` — чистые тесты `FromCounter` (null/0/1/255/отрицательный) и интеграционные на реальном PostgreSQL (настоящий каркас `db/webshelf_skeleton.sql`): найден/счётчик 1/счётчик 0/не найден/пустой/пробельный/обрезка пробелов.
- `WebShelf.Tests/CountdownLockoutTests.cs` — исходное состояние, неположительный старт, декремент, полный отсчёт 15 с (снятие ровно на 15-м тике), отсутствие ухода ниже нуля, перезапуск, тики до старта.
- `WebShelf.Tests/RegistrationApplicationFormTests.cs` — все поля с `required`, типы email/tel и плейсхолдер маски, чек-бокс согласия со ссылкой на политику и 152-ФЗ, кнопка «Подать заявку» — type=button без обработчика, отсутствие ошибок валидации в исходном рендере (HtmlRenderer).

Интеграционные тесты чекера выполняются при заданной переменной окружения `WEBSHELF_TEST_PG` (PostgreSQL 14+ с правами создания баз данных), иначе пропускаются — как `DbSchemaIntegrationTests`.

Результат прогона (Linux, .NET SDK 10.0.403, PostgreSQL 16.4, `WEBSHELF_TEST_PG` задан): **613 тестов, 0 упало, 608 прошло, 5 пропущено** (пропущенные — Windows-специфичные тесты KeyStore: HKCU/DPAPI). Без `WEBSHELF_TEST_PG` интеграционные тесты чекера пропускаются автоматически.

Упавших тестов, не связанных с задачей, не обнаружено: базовый прогон на коммите 2cf3a46 до изменений — 491 тест, 0 упало.
