# Активация разрешения

## Назначение

Окно «Активация разрешения» (страница `/entry`, компонент `Entry.razor`) — точка входа для пользователя, который ещё не имеет доступа к системе и должен активировать разрешение по выданному ключу («Пермит»). Окно открывается с окна «Вход в систему» кнопкой «Зарегистрироваться» и предназначено для последующего обмена разрешения на учётную запись/доступ (логика обмена будет реализована отдельной задачей).

**Реализовано (визуальный каркас):** окно, поле и кнопка без серверной логики.

## Поведение (реализовано)

1. На окне «Вход в систему» добавлена кнопка **«Зарегистрироваться»** (стиль вторичной кнопки `ws-btn-secondary` — прозрачный фон со светлой границей, см. [[Стиль окон]], раздел 6.4). Кнопка имеет `type="button"` и не отправляет форму входа.
2. Клик по кнопке переключает отображение страницы: окно «Вход в систему» сменяется окном «Активация разрешения». Окна показываются **по очереди** — на странице всегда ровно одно окно.
3. Окно «Активация разрешения» содержит одно обязательное текстовое поле **«Пермит»** (ввод не маскируется, плейсхолдер «Введите ключ разрешения») и кнопку **«Продолжить»**. Кнопка пока не выполняет действий (заглушка); реальная валидация поля и обработка ключа появятся вместе с логикой активации.
4. Кнопка закрытия «×» окна возвращает пользователя на окно «Вход в систему»: у окна заданы `CanClose="true"` и колбэк `OnClose` (уведомление проходит через `AppWindow.razor.js` → `NotifyClosedAsync` → `Entry.ClosePermitActivation`).

## Решения

**Решение (два окна — по очереди, а не одновременно):** страницы WebShelf строятся как «одно окно на экране»; окно входа принципиально неоткрываемое (`CanClose="false"`). Показ окон по очереди исключает конфликт фокуса и фона страницы.

**Решение (фон страницы ведёт страница):** фон `body.ws-window-page` ставится/снимается в `OnAfterRenderAsync`/`DisposeAsync` самой страницы `Entry.razor`, оба окна рендерятся с `ApplyPageBackground="false"`. Причина: при смене окон `DisposeAsync` старого окна может выполниться после первого рендера нового — при управлении фоном из окон класс снимался бы уже после установки новым окном (мигание/пропажа фона).

**Решение (иконка окон):** иконка заголовка всегда `WS` — единый идентификатор для всех окон приложения, менять от окна к окну запрещено (см. [[Стиль окон]], раздел 8, пункт 4).

## Ограничения текущей реализации

- Кнопка «Продолжить» не выполняет действий; значение поля «Пермит» никуда не отправляется.
- Поле помечено обязательным (`required`), но валидация на сервере отсутствует — появится вместе с логикой активации.
- Переключение окон не сохраняет введённый «Пермит»: возврат на окно входа и обратно сбрасывает ввод.
