# Группы пользователей

Разделение прав доступа в WebShelf осуществляется через управление группами в AD. Схема именования групп привязана к экземпляру приложения: `WebShelf-{InstanceIdShort}-{Назначение}`.

## Группа доступа (реализовано)

| Группа | Назначение |
| --- | --- |
| `WebShelf-{InstanceIdShort}-Users` | "Пропуск" в систему. Членство проверяется при входе (`Domain.ValidateAdCredentials`); пользователи вне группы не допускаются, даже с валидной парой Login / Password |

- `{InstanceIdShort}` - первые 12 символов InstanceId (ULID) в нижнем регистре. InstanceId генерируется автоматически при первом запуске (Release), хранится в реестре `HKCU\Software\WebShelf\Encryption` (значение `InstanceId`) под защитой DPAPI; актуальное значение InstanceIdShort печатается в лог при старте приложения.
- **Debug-сборка:** InstanceId фиксирован и состоит из 26 нулей (группы вида `WebShelf-000000000000-Users`), реестр не используется. Это позволяет при тестировании на разных компьютерах обращаться к одним и тем же группам AD. Группы для отладки создаются вручную один раз; при переходе на Release-сборку InstanceId генерируется заново, и группы создаются под него.
- На текущем этапе группы создает системный администратор вручную (см. `Server.conf.template`).
- Проверяется только прямое членство в группе (вложенные группы не учитываются).
- Получение списка разрешенных пользователей в коде пока не реализовано: прежний метод (`Domain.GetAllUsers`) удален как атавизм ранних коммитов и будет переписан с нуля по новым требованиям при появлении администрирования пользователей.

## Ролевые группы (концепт, пока не брать в работу)

Планируемые ролевые группы и соответствующие им уровни привилегий (описание ролей - в [[Пользователи]], раздел "Разделение учетных записей по уровню привилегий"):

| Группа | Роль |
| --- | --- |
| `WebShelf-{InstanceIdShort}-Administrator` | 0) Администратор |
| `WebShelf-{InstanceIdShort}-Director` | 1) Директор |
| `WebShelf-{InstanceIdShort}-BIMManager` | 2) BIM-менеджер |
| `WebShelf-{InstanceIdShort}-Manager` | 3) Менеджер |
| `WebShelf-{InstanceIdShort}-GIP` | 4) ГИП |
| `WebShelf-{InstanceIdShort}-GroupLeader` | 5) Руководитель группы |
| `WebShelf-{InstanceIdShort}-Executor` | 6) Исполнитель |
| `WebShelf-{InstanceIdShort}-ExternalExecutor` | 7) Внешний исполнитель |
| `WebShelf-{InstanceIdShort}-Customer` | 8) Заказчик |
| `WebShelf-{InstanceIdShort}-Guest` | 9) Гость |

Требования к ролевой модели:
0) В системе, в каждый момент времени, должен быть минимум один администратор.
1) Один пользователь может состоять в нескольких ролевых группах; приоритет привилегий при пересечении ролей определяется при реализации ролевой модели.
2) Назначение ролей - добавление/удаление пользователя в соответствующей группе AD средствами AD (в перспективе - из WebShelf под системной учетной записью).
