# Группы пользователей

Разделение прав доступа в WebShelf осуществляется через управление группами в AD. Схема именования групп привязана к экземпляру приложения: `WebShelf-{InstanceIdShort}-{Назначение}`.

## Группа доступа (реализовано)

| Группа | Назначение |
| --- | --- |
| `WebShelf-{InstanceIdShort}-Users` | "Пропуск" в систему. Членство проверяется при входе (`Domain.ValidateAdCredentials`); пользователи вне группы не допускаются, даже с валидной парой Login / Password |

- `{InstanceIdShort}` - первые 12 символов InstanceId (ULID) в нижнем регистре. InstanceId генерируется автоматически при первом запуске (Release), хранится в реестре `HKCU\Software\WebShelf\Encryption` (значение `InstanceId`) под защитой DPAPI; актуальное значение InstanceIdShort печатается в лог при старте приложения.
- **Debug-сборка:** InstanceId фиксирован и состоит из 26 нулей (группы вида `WebShelf-000000000000-Users`), реестр не используется. Это позволяет при тестировании на разных компьютерах обращаться к одним и тем же группам AD. Группы для отладки создаются вручную один раз; при переходе на Release-сборку InstanceId генерируется заново, и группы создаются под него.
- На текущем этапе группы создаются приложением автоматически при старте (см. раздел «Создание групп приложением» ниже).
- Проверяется только прямое членство в группе (вложенные группы не учитываются).
- Получение списка разрешенных пользователей в коде пока не реализовано: прежний метод (`Domain.GetAllUsers`) удален как атавизм ранних коммитов и будет переписан с нуля по новым требованиям при появлении администрирования пользователей.

### Создание групп приложением (реализовано)

Логика выполняется при старте приложения (`Program.Main`) после считывания конфигурации (мастер-ключ, инициализация домена, проверка сервисной УЗ):

1) `Domain.FillRequiredGroupsFromTemplates(AppRoleCatalog.GetGroupNameTemplates())` — формирует `_requiredGroups` из списка шаблонов имен групп, подставляя вместо заполнителя `{InstanceIdShort}` короткий префикс InstanceId (12 символов, нижний регистр). Состав шаблонов задается каталогом ролей `AppRoleCatalog`: группа доступа `Users` и по одной группе на каждую роль с суффиксом (под Гостя группа не создается). Пример: `WebShelf-{InstanceIdShort}-Administrator` → `WebShelf-000000000000-Administrator` (Debug-сборка).
2) `Domain.EnsureRequiredGroupsExist` — проверяет существование каждой группы списка в AD и создает отсутствующие; все операции с AD выполняются от имени сервисной учетной записи из `Server.conf` (`domainuser`/`sdomainuser`). Возвращаемое значение: `true`, если все группы существуют или успешно созданы (в том числе при пустом списке), `false` — при пустых именах в списке или ошибке проверки/создания.
3) Если формирование списка или проверка/создание завершились ошибкой, приложение завершается с записью в лог сообщения о невозможности создать необходимые группы (Fatal). При успехе загрузка приложения продолжается.

- Шаблоны имен строятся из каталога ролей `AppRoleCatalog.GetGroupNameTemplates()`: группа доступа `Users` и группы всех ролей с суффиксом (Гость исключен — под него группа не нужна).
- Заполнитель распознается без учета регистра и может встречаться в шаблоне несколько раз; пробелы по краям шаблона обрезаются; дубликаты имен отбрасываются.
- Шаблон, совсем не содержащий заполнителя, используется как имя группы без изменений, без предупреждения в логе.
- Шаблон с некорректным заполнителем (опечатка вида `{InstanseIdShort}`, незакрытая или лишняя фигурная скобка) в список групп не добавляется: в лог пишется предупреждение, формирование списка продолжается (защита от опечатки в заполнителе).
- Отсутствующие группы создаются как группы безопасности **локальные в домене** (Domain Local) с описанием «Группа безопасности WebShelf (экземпляр {InstanceIdShort})».
- Для создания групп сервисной учетной записи потребуются права на создание групп в соответствующем контейнере AD (сейчас ей достаточно прав только на чтение AD).
- После создания групп приложение проверяет группу администраторов (`Domain.GetGroupMemberNames`): если в ней нет ни одного участника, в лог пишется предупреждение о нарушении требования наличия минимум одного администратора (запуск не блокируется — группа могла быть только что создана).

## Ролевые группы (реализовано)

Ролевые группы и соответствующие им уровни привилегий (описание ролей - в [[Пользователи]], раздел "Разделение учетных записей по уровню привилегий"). Группы создаются приложением автоматически при старте.

| Группа                                        | Роль                   |
| --------------------------------------------- | ---------------------- |
| `WebShelf-{InstanceIdShort}-Administrator`    | 0) Администратор       |
| `WebShelf-{InstanceIdShort}-Director`         | 1) Директор            |
| `WebShelf-{InstanceIdShort}-BIMManager`       | 2) BIM-менеджер        |
| `WebShelf-{InstanceIdShort}-Manager`          | 3) Менеджер            |
| `WebShelf-{InstanceIdShort}-GIP`              | 4) ГИП                 |
| `WebShelf-{InstanceIdShort}-GroupLeader`      | 5) Руководитель группы |
| `WebShelf-{InstanceIdShort}-Executor`         | 6) Исполнитель         |
| `WebShelf-{InstanceIdShort}-ExternalExecutor` | 7) Внешний исполнитель |
| `WebShelf-{InstanceIdShort}-Customer`         | 8) Заказчик            |

Гость - отдельной группы не имеет: это пользователь без единой ролевой группы (fallback при отсутствии совпадений, см. [[Пользователи]], раздел "Вычисление роли").

Требования к ролевой модели:
0) В системе, в каждый момент времени, должен быть минимум один администратор (проверяется при старте, предупреждение в лог).
1) Один пользователь может состоять в нескольких ролевых группах: действует старшая роль (наименьший индекс старшинства из `AppRoleCatalog`).
2) Назначение ролей - добавление/удаление пользователя в соответствующей группе AD средствами AD (в перспективе - из WebShelf под системной учетной записью).

### Параметры ролевой модели в Server.conf (реализовано)

| Ключ | Назначение | Диапазон | По умолчанию |
| --- | --- | --- | --- |
| `rolettl` | TTL кэша роли пользователя в `RoleResolver` | 10–300 с | 60 с |
| `rolepoll` | Интервал фонового опроса ролевых групп AD (`RoleRefreshService`) | 10–300 с | 30 с |

Значение вне диапазона, нечисловое или отсутствующее заменяется значением по умолчанию; сами ключи опциональны. Смена роли доезжает до открытых сессий не позже `rolepoll`. Подробнее - см. [[Пользователи]], раздел "Вычисление роли".
