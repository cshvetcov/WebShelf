# 0045 — Вынос эндпоинтов входа и выхода

- **Хеш:** `681344a`
- **Дата:** 2026-11-04
- **Автор:** Constantine
- **Сообщение:** refactor: вынос эндпоинтов входа/выхода из Program.cs в AccountEndpoints (шаг 1 декомпозиции)
- **Изменено файлов:** 9

## Суть изменений

- Первый шаг декомпозиции по дорожной карте: обработчики `LoginAsync`, `LogoutAsync` и вспомогательный `IsLocalUrl` перенесены из `Program.cs` (608 → 384 строки) в новый класс `Classes/Security/AccountEndpoints.cs` (260 строк). Перенос механический: сигнатуры обработчиков (параметры, внедряемые minimal-API из DI) не изменились; маршруты `POST /account/login` и `POST /account/logout`, состав и сроки cookie-клеймов (14 дней при «Запомнить меня», иначе 8 часов), схемы ответов и семантика двойного контура CSRF сохранены.
- Точка подключения в `Program.cs` заменена на метод-расширение `app.MapAccountEndpoints()`; методы обработчиков остались статическими, класс — `internal`.
- Единственное сознательное изменение в перенесённом коде (разрешено принципом 6 дорожной карты): значение `Class=` в шаблонах логов изменено с `WebShelf.Program` на `WebShelf.Classes.Security.AccountEndpoints`.
- В `Data` добавлена внутренняя тестовая точка `CreateWithDomain(Domain)` — фабрика экземпляра с уже установленным доменом, минуя чтение Server.conf (деталь шага 1 дорожной карты; производственное поведение не меняется).
- Новые тесты `AccountEndpointsTests` (15 методов, 28 кейсов): таблица `IsLocalUrl` из 14 случаев (включая протокол-относительные `//host` и `/\host` — защита от open redirect), ветки обработчика входа (неверный antiforgery-токен → 302 `error=invalid`; активная блокировка → `error=locked` с остатком секунд; отсутствие домена, пустое имя, пропущенный пароль → `error=invalid`; порог блокировки из обработчика → точный `retry=30`; неожиданное исключение → `error=server`; недоступный AD при инициализированном домене → `error=server`, только на Windows), ветки выхода (неверный токен → 400; три признака fetch-запроса — Accept: application/json, X-Requested-With, Sec-Fetch-Mode — → 204; обычный POST-переход → 302 `/entry`). Подмены `IAntiforgery` и `IAuthenticationService` вынесены в `AccountEndpointTestFakes`.
- Сценарий успешного входа (состав клеймов, сроки cookie, возврат по ReturnUrl) недоступен юнит-тесту: `Domain.ValidateAdCredentials` нельзя подменить без изменения производственного кода (метод не виртуальный, конструктор `Domain` требует мастер-ключ DPAPI). Проверяется ручной смоук-проверкой на Windows — решение зафиксировано в дорожной карте.
- Документация: README — структура репозитория и состав покрытия тестами; «Пространства имен» — назначение `WebShelf.Classes.Security` дополнено эндпоинтами входа/выхода; актуализирована ссылка на расположение `LoginAsync` в комментарии Entry.razor.
