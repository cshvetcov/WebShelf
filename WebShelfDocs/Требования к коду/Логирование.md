
## 1. Используемая библиотека

- Используется только **Serilog** (`using Serilog;`).
- Статический доступ: `Log.Information(...)`, `Log.Warning(...)`, `Log.Error(...)`, `Log.Debug(...)`, `Log.Fatal(...)`.
- Не вводить другие логгеры (`ILogger<T>`, `Console.WriteLine`, `Debug.WriteLine` и т.п.).

---

## 2. Обязательные свойства в каждом сообщении

Почти все существующие сообщения содержат структурированные свойства:

```csharp
Class={Class}, Method={Method}
```

### Как правильно:

```csharp
private const string ClassName = "WebShelf.Classes.Service.ИмяКласса";

// внутри метода
const string method = nameof(ИмяМетода);

Log.Information("Сообщение. Class={Class}, Method={Method}", ClassName, method);
Log.Error(ex, "Ошибка. Class={Class}, Method={Method}", ClassName, method);
```

- `ClassName` — константа с полным именем класса.
- `method` — локальная константа через `nameof(...)`.
- Для методов в `Program.cs` используется строка `"WebShelf.Program"`.

---

## 3. Выбор уровня логирования

| Уровень       | Когда использовать                                                      | Примеры из кода                                                       |
| ------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `Information` | Штатный успешный ход выполнения                                         | Старт, успешная инициализация домена, успешный выход                  |
| `Warning`     | Ожидаемые/обрабатываемые проблемы, не являющиеся сбоем                  | Неудачный вход, блокировка, неверный antiforgery, некорректные данные |
| `Error`       | Ошибки выполнения операций (с исключением или без)                      | Ошибка чтения конфига, ошибка AD, необработанное исключение           |
| `Fatal`       | Критические ошибки, после которых приложение не может продолжать работу | Не удалось загрузить мастер-ключ или конфигурацию                     |
| `Debug`       | Детальная отладочная информация (разбор строк конфига и т.п.)           | Пропущенные строки конфигурации                                       |

## 4. Маскирование чувствительных данных (обязательно)

**Реальные имена учётных записей в логи писать запрещено.**

| Тип учётной записи  | Значение, которое нужно писать в лог |
| ------------------- | ------------------------------------ |
| Сервисная УЗ        | `SystemAccount`                      |
| Пользовательская УЗ | `UserAccount`                        |

### Примеры правильного использования:

```csharp
// Сервисная учётная запись
Log.Information(
    "Домен инициализирован. Domain={Domain}, User={User}. Class={Class}, Method={Method}",
    domainName, "SystemAccount", ClassName, method);

// Пользовательская учётная запись
Log.Warning(
    "Неудачная попытка входа. Ip={Ip}, User={User}, LockedSec={Sec}. Class={Class}, Method={Method}",
    clientIp, "UserAccount", lockedSec, className, method);

// Ключ блокировки
string logKey = key.StartsWith("user:", StringComparison.OrdinalIgnoreCase)
    ? "user:UserAccount"
    : key;
```

Пароли, токены, мастер-ключи и другие секреты в логи **никогда** не попадают.

---

## 5. Формат сообщений

- Сообщения пишутся на **русском языке**.
- Используются **структурированные свойства** Serilog (`{PropertyName}`), а не интерполяция строк.
- При наличии исключения первым аргументом передаётся `Exception`:

```csharp
Log.Error(ex, "Описание ошибки. Class={Class}, Method={Method}", ClassName, method);
```

- Дополнительные полезные свойства добавляются по смыслу (`Ip`, `Domain`, `Path`, `RemainSec` и т.д.), но всегда после основных `Class` и `Method` или в том же стиле.

---

## 6. Обработка исключений

Во всех catch-блоках существующего кода применяется единый шаблон:

```csharp
catch (Exception ex)
{
    Log.Error(ex, "Исключение в {Class}.{Method}", ClassName, method);
    // дальнейшая обработка (return false / редирект и т.д.)
}
```

или более описательный вариант:

```csharp
Log.Error(ex, "Ошибка при нормализации имени пользователя. Class={Class}, Method={Method}, UserName={UserName}",
    ClassName, method, "UserAccount");
```

---

## 7. Константа ClassName

В каждом классе, где есть логирование, объявляется:

```csharp
private const string ClassName = "WebShelf.Classes....ПолноеИмяКласса";
```

Это позволяет единообразно идентифицировать источник сообщения.

---

## 8. Что не нужно делать

- Не логировать реальные имена пользователей и сервисных учётных записей.
- Не использовать разные стили сообщений (смешивать русский/английский, разные форматы свойств).
- Не писать логи без `Class` и `Method`.
- Не использовать `Log.Verbose` / `Log.Fatal` без крайней необходимости (Fatal — только для полной остановки приложения).
- Не создавать собственные sink’и или менять глобальную конфигурацию логгера без согласования.

---

## Краткая шпаргалка при добавлении нового лога

```csharp
private const string ClassName = "WebShelf.Classes....";

// в методе:
const string method = nameof(MyMethod);

try
{
    // ...
    Log.Information("Успешное действие. Class={Class}, Method={Method}", ClassName, method);
}
catch (Exception ex)
{
    Log.Error(ex, "Ошибка при выполнении. Class={Class}, Method={Method}", ClassName, method);
}
```
